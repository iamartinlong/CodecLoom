## 0. 一页速览

### 0.1 这是什么

基于 [Sdcb.SimdCodecs 2.0](https://www.nuget.org/packages/Sdcb.SimdCodecs) 的**纯托管图片 I/O + 文档智能工作台**：一个零原生依赖的编解码核心，同时驱动 Avalonia 桌面客户端、命令行批量工具、ASP.NET Core API 与无依赖 Web 测试台；并带可选的**文档智能模块**（SimdGcdrNet 透印增强 + SimdPaddleOCR 中文 OCR，纯托管、可 AOT）。定位是**验证这套 SDK 能否撑起产品形态**（本地隐私工具 / 图片处理服务 / OCR·CV 输入层 / 扫描件清洗），不是做一个完整图片编辑器。

### 0.2 五件必须记住的事

1. **技术名 ≠ 对外名**。对外叫 `CodecLoom`，但项目名、命名空间、解决方案 `SimdCodecsWorkbench.slnx`、MSIX Identity 仍是 `SimdCodecs.*`。**不要做全仓重命名**，会一次性打断 CI 路径、程序集引用与已签名的 MSIX 链。
2. **零原生依赖是主线**。任何「顺手加个 SkiaSharp / ImageSharp / 原生 DLL」的改动都会抵消 NativeAOT / WASM 这个最大卖点；处理层 `SimdCodecs.Processing` 刻意只依赖 BCL，文档智能模块 `SimdCodecs.Document` 的两个引擎包同样零原生二进制。
3. **上游版本精确锁**（Core `[2.0.0]`，Document 四包均 `[1.0.0]`/`[2.0.0]`），并通过 `ICodecService` 抽象隔离。上游库年轻且单人维护，升级前必须跑完第 6 节全套回归。
4. **CI 里凡直接运行 GUI 子系统 exe（Viewer 的任何发布形态），一律 `shell: bash` 重定向到文件再断言退出码**。pwsh 捕获 GUI 子系统 exe 的 stdout / `$LASTEXITCODE` 不可靠（0 行 + 空码），曾把通过的自检误判为失败（`04-工作日志.md` 第十七轮）。
5. **对本机 GUI 程序做窗口级验证，必须按 PID 过滤窗口**（`EnumWindows` + `GetWindowThreadProcessId`），不能按标题 `FindWindowW`。用户可能正开着旧版实例，按标题会抓到跑旧代码的窗口，导致「修复无效」的误判（第二十一轮三次假失败全是这个原因）；且 HWND 每次启动都重分配，跨运行对比 HWND 无意义。

## 3. 系统全景

### 3.1 分层与依赖方向

```
  Avalonia 窗口 ─┐
  CLI --batch   ─┼──┬─ SimdCodecs.Core（零 UI / 零 Web / 零原生依赖）
  ASP.NET Core ──┘  │    CodecService · ICodecService · BatchService
  Web 测试台 ───────┘    BatchPresets · ImageGuard · CodecServices.Current
                         └── Sdcb.SimdCodecs 2.0.0 + .Heif 2.0.0（精确锁）
                    ├─ SimdCodecs.Processing（可选，只依赖 BCL；Core 不引用它）
                    │    ImageOps · ImageProcessor · CvInput · ProcessingOptions
                    ├─ SimdCodecs.Document（可选，opt-in；Core / Processing 不引用它）
                    │    DocumentGate · GcdrDocumentEnhancer · SimdOcrService
                    │    DocumentPipeline · DocumentRuntime
                    │    └── Sdcb.SimdGcdrNet [1.0.0] / Sdcb.SimdPaddleOCR [2.0.0]
                    │        + Models [1.0.0] / Models.ChineseV6Tiny [1.0.0]（均精确锁）
                    └─ SimdCodecs.Tests（xUnit，真实 Kestrel）
```

- **Core**：只依赖 SimdCodecs；每个能力同时提供「文件路径」与「内存字节」两个入口，服务端全程不落盘。
- **Processing**：与 Core 平级，输入输出都是裸 `byte[]`，Core 不因它沾上原生依赖。
- **Document**：与 Core 平级；`DocumentGate`（`SemaphoreSlim` 闸门，排队超时 HTTP 可中断 / CPU 推理不可中断）、`GcdrDocumentEnhancer`（Lazy 单例，GPU Auto 首推失败自动降级 CPU 并标 `degraded`）、OCR tiny 模型 6.98 MB 作嵌入资源随产物分发（small / medium 不进）。引擎 Apache-2.0 / 模型 MIT。
- **桌面层**：`Bgra32 → WriteableBitmap(Bgra8888, AlphaFormat.Unpremul)` 逐行直拷，不假设 `Stride == RowBytes`；UI 用纯 C# 构建（无 XAML），避开 AOT 下的反射绑定。**深色标题栏**由 `DarkTitleBar.cs` 显式管理：`DWMWA_USE_IMMERSIVE_DARK_MODE(20)`（旧 build 回退 19）+ Win11 `CAPTION_COLOR(35)`/`TEXT_COLOR(36)` 同色底，Opened 后三次覆盖（Avalonia Win32 会按系统色重设）+ 监听系统颜色变化。**窗口图标**从 `avares://` 资源加载（物理文件在仓库根 `assets/`，csproj 用 `..\assets\` + `Link` 引入）。
- **服务层**：`ImageGuard` 在解码前只读文件头校验；响应直接写编码字节 / zip / 裸像素。
- **接口层**：`ICodecService` 由 DI 注入 `CodecServices.Current`；将来回退到 Magick.NET / ImageSharp 只改注册，端点层不动。

### 3.3 一次转换经过哪些文件

1. 入口：`SimdCodecsViewer/MainWindow.cs`（UI）/ `BatchCli.cs` / `DocumentCli.cs`（CLI）/ `SimdCodecs.Api/ImageEndpoints.cs`、`DocumentEndpoints.cs`（HTTP）。
2. 预检：`Core/CodecService.cs` 的 `Inspect*`（只读头）→ 服务端再过 `ImageGuard.Validate`（32 MB / 80 MP / 200 帧，返回 413 / 415 / 422）；文档智能端点再过 `DocumentGate.EnsureEnabled`（501）与 `DocumentLimits`（4 MP → 413、多帧 → 422、闸门满 → 503）。
3. 预设：`Core/BatchPresets.cs` 的 `Apply` 覆盖 `BatchSettings`（目标格式、质量、拆页、页码、源格式过滤）。
4. 解码：`CodecService.Load` / `ImageDecoder.Open(...).GetFrame(i).Decode(...)`，用 `DecodeOptions.Region` / `ScaleDenominator` / `ApplyOrientation` 在**解码阶段**完成裁剪、缩放与 EXIF 转正。
5. 可选处理：`SimdCodecs.Processing/ImageProcessor.cs` 做缩放 / 色调 / 水印 / 裸像素布局。
6. 可选文档智能：`DocumentPipeline.cs` 串联 `enhance → ocr`（`PixelBuffer.Pixels.ToArray() + Stride` 交付 Bgra32）。
7. 编码导出：`ImageCodecs.Encode`，元数据 EXIF / XMP / ICC 原样透传；批量结果打 zip，附 `_manifest.csv` 与 `_report.txt`（单文件失败不影响整批；`--document` 另产 `_document_manifest.csv`）。

| 文档智能 | 默认关（opt-in）；开箱只有 tiny 模型（6.98 MB），GPU 后端失败自动降级 CPU，容器内需自行装 `libvulkan`（Dockerfile 有注释） |

### 4.2 三种启动方式

```bash
# 1) 服务 + Web 测试台（单文件 HTML，无前端依赖）
dotnet run --project SimdCodecs.Api -c Release -- --urls http://127.0.0.1:5080
# 浏览器打开 http://127.0.0.1:5080/

# 2) 桌面工作台
dotnet run --project SimdCodecsViewer -c Release

# 3) 容器（需运行中的 Docker daemon）
docker compose up --build -d
curl http://127.0.0.1:5080/api/ready
```

桌面命令行参数（`SimdCodecsViewer/Program.cs`）：`--batch <输入目录> <输出目录> [预设ID或格式]`、`--document <输入目录> <输出目录> enhance|ocr|both [compare]`（逐张串行 + `_document_manifest.csv`）、`--selftest [输出目录]`、`--smoke`、`--screenshot <png> [宽] [高]`；不带参数才启动 GUI。
API 参数（`SimdCodecs.Api/Program.cs`）：`--apitest` 启动真实 Kestrel 跑全套端点；`--urls`、以及 `--ApiRuntime__A__B=value` / `--Document__X=value` 形式的开关（程序会把 `__` 归一化成 `:`）。

### 4.3 配置、端口与安全默认值

| 配置 | 位置 | 默认 | 说明 |
| --- | --- | --- | --- |
| `ApiRuntime.StructuredLog` | `appsettings.json` | `true` | 单行 JSON 请求日志（requestId / method / path / status / elapsedMs / traceParent） |
| `ApiRuntime.Auth` | 同上 | `false`，Key 空 | 开启后保护所有 `/api/*` 业务端点；`/api/health`、`/api/ready`、静态测试台除外；支持 `X-Api-Key` 与 `Authorization: Bearer`，固定时间比较 |
| `ApiRuntime.RateLimit` | 同上 | `false`，60 次 / 60 秒 | 按客户端 IP 固定窗口，超限 429 + `Retry-After` |
| Kestrel `MaxRequestBodySize` | 同上 / `Program.cs` | 64 MB | 业务层 `ImageGuard` 另限单文件 32 MB |
| `Document.Enabled` | `appsettings.json` | **`false`（opt-in）** | 关闭时 `/api/enhance` `/api/ocr` `/api/document` 返回 501 |
| `Document.OcrRequireAuth` | 同上 | **`true`** | OCR 类端点即使全局鉴权未开也要求 API Key（401） |
| `Document.MaxPixels` / `MaxFrames` / `Timeout` / `Backend` | 同上 | 4 MP / 1 / 60 s / `Auto` | 超限 413 / 422；排队超 `Timeout` 503；`Auto` 失败降级 CPU 并标 `degraded` |
| `/api/metrics` | `ApiRuntime.cs` | 进程内计数 | `?format=prometheus` 输出 Prometheus 文本；重启清零、无额外 NuGet 依赖；**OCR 日志与指标只记统计不记正文** |
| compose 端口 | `docker-compose.yml` | `5080:8080` | `read_only: true`、`cap_drop: ALL`、`tmpfs /tmp`、1 GB 内存 / 2 CPU 上限 |

生产环境**默认全关 / opt-in** 是刻意的：本地开发、测试台与既有回归不依赖任何配置。要开启时用环境变量 `ApiRuntime__Auth__Enabled=true`、`Document__Enabled=true` 等，或命令行 `--Document:Enabled=true`。测试台的 API Key 只存浏览器 `localStorage`。

### 4.4 桌面设置与本地化

- 设置持久化在 `%APPDATA%/SimdCodecsViewer/settings.json`：窗口尺寸、输出目录、预设、缩放、处理参数、文档智能开关、语言等 **21 项**；文件损坏自动回默认值。`Settings.cs` **手写 JSON 生成 + `JsonDocument` 解析**，不是 `JsonSerializer` —— POCO 反射序列化会触发 AOT 的 `IL3050`。
- 界面语言中/英切换见 `L10n.cs`，**切换后需重启生效**；深色主题通过 `RequestedThemeVariant = ThemeVariant.Dark` 设置（Avalonia 11 没有 `FluentTheme.Mode`）。
- **深色标题栏**：窗口内容变暗后 DWM 标题栏不会自动跟随，`DarkTitleBar.cs` 在 `Opened` 后立即 + Dispatcher 后段 + 150 ms 三次覆盖，并监听 `PlatformSettings.ColorValuesChanged` 防运行期被改回。Win10（如交接机 22H2）拿到系统标准暗色；Win11 标题栏底色与 UI 融合（`#141518` / `#E8EAED`）。
- **品牌资产**：改 logo 只需编辑 `tools/gen-logo.py` 的颜色常量并重跑（`python tools/gen-logo.py`），会重新生成 `assets/` 全部位图；`assets/logo.svg` 是矢量主文件，改几何时与脚本同步。窗口图标经 csproj 的 `AvaloniaResource` 嵌入，改文件名需同步 csproj `Link` 与 `MainWindow` 的 `avares://` URI。

### 6.4 常见误判

- 预设批量里 `Skipped` 是**正常业务结果**（源格式不匹配），不是失败；统计里失败与跳过分开。
- 在发布目录里跑 `--selftest` 会留下 `selftest-output/`，**打包前必须清理**，否则污染便携 zip。
- 匿名 `curl` 打 GitHub REST API 会 403 / 限流；已认证查询可用 `git credential fill` 取 token 后带 `Authorization: Bearer` 调 API。**下载 Release asset 必须带 `Accept: application/octet-stream`，否则拿到的是 JSON 元数据**。
- xUnit 共享静态字段会被多个 fixture 并行覆盖，文档智能测试一律用 **per-fixture 实例字段**。
- smoke / GUI 冒烟结果**不应依赖用户本机设置**：标题断言曾写死中文「工作台」，本机 settings.json 残留 `Language=en` 导致误报；已改为语言无关的 `Contains("CodecLoom")`。新增 GUI 断言时同样避免依赖用户可改的持久化状态。
- **验证窗口属性（标题栏色、图标、位置等）时按 PID 过滤，不要按标题抓窗口**——用户可能开着旧版实例（详见 0.2 第 5 条）。

## 8. 关键设计决策（改之前先读）

| 决策 | 理由 | 代价 / 改动影响 |
| --- | --- | --- |
| 纯 BCL 处理层替代 SkiaSharp | 保住「零原生 DLL + NativeAOT + WASM 可跑」主线 | 水印是 FNV 哈希决定相位的**几何图案，不渲染文字字形**；无矢量绘图 / 透视变换；处理层是单线程标量实现，大图需压测 |
| 文档智能合并为单一 `SimdCodecs.Document`（增强 + OCR 共用闸门/限额） | 两引擎同作者、同像素契约，分开会造成两套 opt-in / 闸门 / 合规链路 | 模块内部耦合增强与 OCR；只想要其一也要引入整个模块（模型仅 tiny 进产物） |
| 文档智能默认关（opt-in）+ OCR 端点强制鉴权 | 模型体积 +22 MB、推理占资源；OCR 有数据敏感性 | 用户/部署方必须显式 `Document__Enabled=true`；忘了开会以为功能坏了（501） |
| `SemaphoreSlim` 闸门 + 双重超时 | GPU/CPU 推理不可中断，HTTP `WaitAsync` 先兜底 | CPU 推理超时后线程仍会跑完，只是请求已 503 |
| GPU `Auto` 失败自动降级 CPU | 容器 / 无 GPU 环境开箱即用 | 降级后结果标 `degraded`，质量略降 |
| **CI 直接运行 GUI 子系统 exe 一律 `shell: bash` 重定向文件** | pwsh 捕获 GUI exe 的 stdout / 退出码不可靠（曾误判 AOT job 失败） | 断言逻辑要写成文件检查而非管道捕获 |
| **深色标题栏由应用显式管理（`DarkTitleBar`）** | Avalonia Win32 的 `SetFrameThemeVariant` 只按「系统」颜色主题重设 DWM 属性，内容变暗标题栏不跟随 | Opened 后三次覆盖 + 系统色变化监听；若未来 Avalonia 原生支持按应用主题联动，可删除此模块 |
| **品牌位图由脚本生成、矢量手写，两者同几何** | logo 改色 / 改尺寸可复现，不依赖设计软件 | `tools/gen-logo.py` 与 `assets/logo.svg` 需同步改（over-under 棋盘：i+j 奇偶决定纬线在上） |
| Inno Setup 安装包替代 MSIX 作分发主路径 | 免签名证书、免管理员、带卸载；MSIX 门槛（管理员导入证书）过高 | 无签名 → SmartScreen 提示；商店分发仍需正式证书（X-6） |
| `ICodecService` + 精确锁版本 | 上游年轻、单人维护、有破坏性变更 | 升级必须跑全套回归；替换实现只改 DI 注册 |
| 统一 `Bgra32` 像素 | Avalonia `Bgra8888` 逐行直拷，不假设 Stride；文档智能两个引擎同样吃 Bgra32 | 换 UI 框架需重写 `BitmapFactory.cs` |
| 解码阶段做裁剪/缩放/转正 | 不先解全图，省内存 | 依赖上游 `DecodeOptions`，不能随意换成后处理 |
| `ImageGuard` 头部预检 + `DocumentLimits` | 挡图片炸弹；OCR/增强另限 4 MP / 单帧 | 限额写死在两个 Limits 类，调整需同步测试 |
| 生产化配置**默认全关** | 不破坏本地开发与既有回归 | 上公网必须显式开鉴权与限流 |
| 指标为进程内计数、限流按 IP 固定窗口 | 不引入 Prometheus 客户端包，避免破坏 AOT 与零依赖主张 | 多实例部署时指标/配额不共享，需要外部方案 |
| 手写 JSON（设置、sidecar、日志） | AOT 下反射序列化会触发 `IL2026` / `IL3050` | 加字段需同步手写序列化与解析（设置现为 21 项） |
| 预设数据化、四处共用 | 一次定义，桌面 / CLI / API / 测试台一致 | 新预设要在 `BatchPresets` 加并补测试 |
| 保留技术名、只改对外标识 | 避免打断 CI 路径与签名链 | 仓库里两套名字并存，见 3.2 |
| `.gitattributes` 统一换行 / 二进制标记 | Win/Linux 双矩阵 CI 不出现整文件 diff | 新增二进制扩展名记得补 `binary` 规则 |

## 9. 风险与债务

### 9.1 上游边界

- AVIF / JPEG XL **只能识别不能解码**；HEIF/HEIC **只解码**，不支持编码、alpha 与序列。
- HEVC 专利不在 MIT 授权内，商用前需法务评估。
- .NET 10 是硬门槛；`Stream` 整读进内存，单数组 2 GB 上限；上游 2.0 有破坏性变更（门面类名、像素格式枚举、WebP 默认有损）。
- 上游库年轻、单人维护 —— 靠锁版本 + 抽象层缓解，不自行修上游。文档智能两个引擎包同样年轻（各仅一个版本）。
- 文档智能模型**不支持批量推理 N>1**，`--document` 与 `/api/document` 均为逐张串行。

### 9.2 本项目取舍

- 处理层单线程标量、无 SIMD / 并行；JBIG2 / JPEG 2000 真实样本链路未跑（下载失败，**未伪造结果**）。
- 字体水印 / 矢量绘图 / 透视变换未做；若确需 TrueType 字形，应另加**真正可选**的 Skia 适配项目，不影响现有链路。
- OCR 逐字符框为 CTC 估算，不承诺精确排版；small / medium 模型不进默认产物（体积 24.91 / 95.71 MB）。
- 自动更新（X-6）未做，依赖分发渠道决策；安装包无签名，SmartScreen 首次运行会拦一次。
- 指标重启清零；无多实例共享、无持久化存储、无账号体系。

### 9.3 安全

- 私钥 `SimdCodecsDev.pfx` 与 GitHub PAT 均在本地且被忽略；**任何一次 `git add -f` 都可能造成泄露**，提交前用 `git check-ignore -v` 与 `git grep --cached` 复核。
- `ImageGuard` 是业务层限额，生产部署仍需在反向代理层限制请求体与并发。
- 测试台默认 `AllowAnyOrigin` CORS，公网部署需收紧或加鉴权。
- OCR 端点默认强制鉴权（`Document__OcrRequireAuth=true`），日志与指标只记统计不记识别正文；但增强/OCR 结果本身经 HTTP 返回，公网部署务必走 TLS。

## 10. 排障速查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| **pwsh 捕获 GUI 子系统 exe（Viewer 任何发布形态）得到 0 行输出 + 空退出码** | pwsh 与 GUI 子系统管道交互不可靠（曾致 CI AOT job 误判失败） | CI 里一律 `shell: bash`，输出重定向到文件后断言退出码与关键标记 |
| **按标题 FindWindowW 抓到「旧版」窗口，修复实验全部假失败** | 用户正开着旧实例，且 HWND 每次启动重分配 | 用 `EnumWindows` + `GetWindowThreadProcessId` 按 PID 过滤（先 `Get-Process SimdCodecsViewer` 排查残留） |
| `MSB4018 GenerateAvaloniaResourcesTask` 找不到资源文件 | `AvaloniaResource` Include 写了项目内相对路径，而物理文件在仓库根 `assets/` | 写 `Include="..\assets\appicon-256.png" Link="Assets/appicon-256.png"`；改文件名需同步 `avares://` URI |
| `MSB4018` / `MSB3027`，DLL 被占用 | 5080 的 `dotnet` host 锁住 Core / Processing 输出 | 编译前停掉 `SimdCodecs.Api.exe` / 相关 dotnet 进程，编译完再启动 |
| **AOT 发布找不到 `advapi32.lib`** | Windows SDK 不完整或装在非标准盘。**交接本机即此情况：`Lib\10.0.26100.0` 的 um 库目录为空，文件物理缺失** | 盘符问题可注入 `LIB` / `WindowsSdkDir` / `WindowsSDKVersion`；库缺失只能补装「Windows SDK for Desktop C++ x64 Apps」。CI 用 `ilammy/msvc-dev-cmd@v1`，是最可靠的验证途径 |
| 文档智能端点 501 | `Document__Enabled` 默认 false | 设 `Document__Enabled=true` 重启；桌面端在「文档智能」卡片开 opt-in 开关 |
| OCR 端点 401 | `Document__OcrRequireAuth` 默认 true 且未带 API Key | 带 `X-Api-Key`，或显式 `Document__OcrRequireAuth=false`（不建议公网） |
| 文档智能 503 | 闸门满排队超过 `Document.Timeout`（默认 60 s） | 调大 Timeout 或降低并发；GPU 推理不可中断属预期 |
| GPU 后端失败后变慢 | Auto 降级 CPU 并标 `degraded` | 容器内装 `libvulkan` 或显式 `Document__Backend=cpu` |
| ISCC 编译报找不到语言文件 | `ChineseSimplified.isl` 必须与 iss 同目录（仓库 `installer/`） | 保持 checkout 完整；不要写 `compiler:Languages\` 路径 |
| Linux GUI 冒烟起不来 | runner 缺 X11 / Skia 运行库 | 已在工作流补 `libx11-6` 等 9 个包并用 `xvfb-run -a` |
| 静态测试台 404 | 从解决方案根目录启动时内容根不对 | `WebApplicationOptions` 固定 `ContentRootPath = AppContext.BaseDirectory`、`WebRootPath = "wwwroot"`；csproj 把 `wwwroot/**` 复制到输出 |
| `--ApiRuntime__Auth__Enabled` 不生效 | 命令行配置用 `:` 分层 | 用 `--ApiRuntime:Auth:Enabled=true`，或依赖 `NormalizeRuntimeArg` 自动把 `__` 转成 `:` |
| `fatal: unable to write credential store` | 凭据助手回写被沙箱拒 | push 已成功，`git ls-remote` 复核，勿重推 |
| GitHub REST API 403 / 限流 | 匿名调用 | 用 `git credential fill` 取 token 带认证调用；下载 Release asset 加 `Accept: application/octet-stream` |
| `makeappx unpack /d /tmp/...` 看不到目录 | Windows 工具不认 Git Bash 的 `/tmp` | 用 Python `zipfile` 直接读 MSIX 内清单 |
| 打出来的不是合法 zip / 中文名乱码 | GNU tar 不产 zip；编码问题 | 用 Windows `System32/tar.exe` 或 `Compress-Archive`，包内说明文件用英文名 |
| 便携 zip 里混进测试输出 | 在发布目录跑过 `--selftest` | 打包前删 `selftest-output/` 并核对条目数 |
| xUnit 文档智能测试互相干扰 | 共享静态字段被多 fixture 并行覆盖 | 用 per-fixture 实例字段（`DocumentTests` 已是范例） |
| Avalonia 主题报错 | 11.x 无 `FluentTheme.Mode`；`CornerRadius` Setter 需对象 | 用 `RequestedThemeVariant = ThemeVariant.Dark`；Setter 传 `new CornerRadius(6)` |
| 暗色模式下标题栏仍为白色 | DWM 标题栏不跟随应用主题；Avalonia 会按系统色重设 | `DarkTitleBar.Attach(window)` 已接入 `MainWindow`；确认新编译产物、不要读旧实例验证 |
| 验证 exe 图标时被拦（PowerShell `Add-Type` / COM） | 沙箱安全策略禁止动态编译与 COM 实例化 | 用 Python ctypes：`ExtractIconExW` 在 **shell32**（不是 user32） |
| `.gitignore` 规则不生效 | pattern 后跟了行尾注释 | 注释必须独立成行，改完用 `git check-ignore -v` 实测 |
| API Key 的 curl 验证被安全策略拦截 | 命令行带密钥被拦 | 改用 xUnit fixture（同参数自宿主）+ 5090 实例结构化日志作证据 |
