## 0. 一页速览

### 0.1 这是什么

基于 [Sdcb.SimdCodecs 2.0](https://www.nuget.org/packages/Sdcb.SimdCodecs) 的**纯托管图片 I/O 工作台**：一个零原生依赖的编解码核心，同时驱动 Avalonia 桌面客户端、命令行批量工具、ASP.NET Core API 与无依赖 Web 测试台。定位是**验证这套 SDK 能否撑起三种产品形态**（本地隐私工具 / 图片处理服务 / OCR·CV 输入层），不是做一个完整图片编辑器。

### 0.2 三件必须记住的事

1. **技术名 ≠ 对外名**。对外叫 `CodecLoom`，但项目名、命名空间、解决方案 `SimdCodecsWorkbench.slnx`、MSIX Identity 仍是 `SimdCodecs.*`。**不要做全仓重命名**，会一次性打断 CI 路径、程序集引用与已签名的 MSIX 链。
2. **零原生依赖是主线**。任何「顺手加个 SkiaSharp / ImageSharp / 原生 DLL」的改动都会抵消 NativeAOT / WASM 这个最大卖点；处理层 `SimdCodecs.Processing` 刻意只依赖 BCL。
3. **上游版本精确锁 `[2.0.0]`**，并通过 `ICodecService` 抽象隔离。上游库年轻且单人维护，升级前必须跑完第 6 节全套回归。

## 3. 系统全景

### 3.1 分层与依赖方向

```
  Avalonia 窗口 ─┐
  CLI --batch   ─┼──┬─ SimdCodecs.Core（零 UI / 零 Web / 零原生依赖）
  ASP.NET Core ──┘  │    CodecService · ICodecService · BatchService
  Web 测试台 ───────┘    BatchPresets · ImageGuard · CodecServices.Current
                         └── Sdcb.SimdCodecs 2.0.0 + .Heif 2.0.0（精确锁）
                    ┌─ SimdCodecs.Processing（可选，只依赖 BCL；Core 不引用它）
                    │    ImageOps · ImageProcessor · CvInput · ProcessingOptions
                    └─ SimdCodecs.Tests（xUnit，真实 Kestrel）
```

- **Core**：只依赖 SimdCodecs；每个能力同时提供「文件路径」与「内存字节」两个入口，服务端全程不落盘。
- **Processing**：与 Core 平级，输入输出都是裸 `byte[]`，Core 不因它沾上原生依赖。
- **桌面层**：`Bgra32 → WriteableBitmap(Bgra8888, AlphaFormat.Unpremul)` 逐行直拷，不假设 `Stride == RowBytes`；UI 用纯 C# 构建（无 XAML），避开 AOT 下的反射绑定。
- **服务层**：`ImageGuard` 在解码前只读文件头校验；响应直接写编码字节 / zip / 裸像素。
- **接口层**：`ICodecService` 由 DI 注入 `CodecServices.Current`；将来回退到 Magick.NET / ImageSharp 只改注册，端点层不动。

### 3.2 命名对照（最容易踩的一处）

| 对外 | 技术名（保留，勿改） |
| --- | --- |
| CodecLoom / 仓库 `CodecLoom` / 中文「解码织台」 | 项目 `SimdCodecs.Core` `SimdCodecs.Processing` `SimdCodecsViewer` `SimdCodecs.Api` `SimdCodecs.Tests` |
| 窗口 Title、MSIX DisplayName、compose 服务名、workflow name | 命名空间 `SimdCodecs.*`、解决方案 `SimdCodecsWorkbench.slnx`、MSIX Identity `SimdCodecs.Workbench` 与 Publisher（必须与签名证书 subject 一致） |
| GHCR `ghcr.io/iamartinlong/codecloom`（**必须小写**） | workflow 中的 `tr '[:upper:]' '[:lower:]'` 小写化步骤，不能删 |

### 3.3 一次转换经过哪些文件

1. 入口：`SimdCodecsViewer/MainWindow.cs`（UI）/ `BatchCli.cs`（CLI）/ `SimdCodecs.Api/ImageEndpoints.cs`（HTTP）。
2. 预检：`Core/CodecService.cs` 的 `Inspect*`（只读头）→ 服务端再过 `ImageGuard.Validate`（32 MB / 80 MP / 200 帧，返回 413 / 415 / 422）。
3. 预设：`Core/BatchPresets.cs` 的 `Apply` 覆盖 `BatchSettings`（目标格式、质量、拆页、页码、源格式过滤）。
4. 解码：`CodecService.Load` / `ImageDecoder.Open(...).GetFrame(i).Decode(...)`，用 `DecodeOptions.Region` / `ScaleDenominator` / `ApplyOrientation` 在**解码阶段**完成裁剪、缩放与 EXIF 转正。
5. 可选处理：`SimdCodecs.Processing/ImageProcessor.cs` 做缩放 / 色调 / 水印 / 裸像素布局。
6. 编码导出：`ImageCodecs.Encode`，元数据 EXIF / XMP / ICC 原样透传；批量结果打 zip，附 `_manifest.csv` 与 `_report.txt`（单文件失败不影响整批）。

## 4. 环境与运行

### 4.1 前置条件

| 项 | 要求 |
| --- | --- |
| SDK | **.NET 10 SDK**（`dotnet --version >= 10.0.100`）；`.slnx` 需要较新的 SDK 支持 |
| 操作系统 | Windows（MSIX / 本地 NativeAOT / GUI）、Linux（CI 回归 + Xvfb GUI 冒烟）、容器（chiseled） |
| 本地 NativeAOT | 需 MSVC 链接工具链与 Windows SDK；CI 用 `ilammy/msvc-dev-cmd@v1` 显式准备 |
| Docker | 本机 daemon 未常开；CI 内的 buildx 已验证可用 |

### 4.2 三种启动方式

```bash
# 1) 服务 + Web 测试台（单文件 HTML，无前端依赖）
dotnet run --project SimdCodecs.Api -c Release -- --urls http://127.0.0.1:5080
# 浏览器打开 http://127.0.0.1:5080/

# 2) 桌面工作台
dotnet run --project SimdCodecsViewer -c Release

# 3) 容器（需运行中的 Docker daemon）
docker compose up --build -d
curl http://127.0.0.1:5080/api/ready
```

桌面命令行参数（`SimdCodecsViewer/Program.cs`）：`--batch <输入目录> <输出目录> [预设ID或格式]`、`--selftest [输出目录]`、`--smoke`、`--screenshot <png> [宽] [高]`；不带参数才启动 GUI。
API 参数（`SimdCodecs.Api/Program.cs`）：`--apitest` 启动真实 Kestrel 跑全套端点；`--urls`、以及 `--ApiRuntime__A__B=value` 形式的生产化开关（程序会把 `__` 归一化成 `:`）。

### 4.3 配置、端口与安全默认值

| 配置 | 位置 | 默认 | 说明 |
| --- | --- | --- | --- |
| `ApiRuntime.StructuredLog` | `appsettings.json` | `true` | 单行 JSON 请求日志（requestId / method / path / status / elapsedMs / traceParent） |
| `ApiRuntime.Auth` | 同上 | `false`，Key 空 | 开启后保护所有 `/api/*` 业务端点；`/api/health`、`/api/ready`、静态测试台除外；支持 `X-Api-Key` 与 `Authorization: Bearer`，固定时间比较 |
| `ApiRuntime.RateLimit` | 同上 | `false`，60 次 / 60 秒 | 按客户端 IP 固定窗口，超限 429 + `Retry-After` |
| Kestrel `MaxRequestBodySize` | 同上 / `Program.cs` | 64 MB | 业务层 `ImageGuard` 另限单文件 32 MB |
| `/api/metrics` | `ApiRuntime.cs` | 进程内计数 | `?format=prometheus` 输出 Prometheus 文本；重启清零、无额外 NuGet 依赖 |
| compose 端口 | `docker-compose.yml` | `5080:8080` | `read_only: true`、`cap_drop: ALL`、`tmpfs /tmp`、1 GB 内存 / 2 CPU 上限 |

生产环境**默认全关**是刻意的：本地开发、测试台与既有回归不依赖任何配置。要开启时用环境变量 `ApiRuntime__Auth__Enabled=true`、`ApiRuntime__Auth__Key=<secret>`，或命令行 `--ApiRuntime:Auth:Enabled=true`。测试台的 API Key 只存浏览器 `localStorage`。

### 4.4 桌面设置与本地化

- 设置持久化在 `%APPDATA%/SimdCodecsViewer/settings.json`：窗口尺寸、输出目录、预设、缩放、处理参数、语言等；文件损坏自动回默认值。`Settings.cs` **手写 JSON 生成 + `JsonDocument` 解析**，不是 `JsonSerializer` —— POCO 反射序列化会触发 AOT 的 `IL3050`。
- 界面语言中/英切换见 `L10n.cs`，**切换后需重启生效**；深色主题通过 `RequestedThemeVariant = ThemeVariant.Dark` 设置（Avalonia 11 没有 `FluentTheme.Mode`）。

### 7.2 四个 job 在做什么

- **test**：`checkout` → `setup-dotnet 10.0.x` → restore → Release build → xUnit + 覆盖率 → `--selftest` → GUI 冒烟（Windows 直跑 / Linux `xvfb-run`）→ `--apitest` → 真实 3 页 TIFF `scan-split` 批量 → publish API + 单文件 → 发布产物存在性/可运行校验 → 上传 trx 与 coverage。
- **aot**：`ilammy/msvc-dev-cmd@v1` 准备 MSVC → `PublishAot=true` 发原生 exe → 自检 + 批量。
- **docker**：镜像名小写化 → 登录 GHCR（`GITHUB_TOKEN`）→ metadata 生成 `latest` / 分支 / `sha-<短 SHA>` → buildx 构建推送。`needs` 门禁确保回归全绿才发。

## 8. 关键设计决策（改之前先读）

| 决策 | 理由 | 代价 / 改动影响 |
| --- | --- | --- |
| 纯 BCL 处理层替代 SkiaSharp | 保住「零原生 DLL + NativeAOT + WASM 可跑」主线 | 水印是 FNV 哈希决定相位的**几何图案，不渲染文字字形**；无矢量绘图 / 透视变换；处理层是单线程标量实现，大图需压测 |
| `ICodecService` + 精确锁 `[2.0.0]` | 上游 2.0 发布仅两天、单人维护、有破坏性变更 | 升级必须跑全套回归；替换实现只改 DI 注册 |
| 统一 `Bgra32` 像素 | Avalonia `Bgra8888` 逐行直拷，不假设 Stride | 换 UI 框架需重写 `BitmapFactory.cs` |
| 解码阶段做裁剪/缩放/转正 | 不先解全图，省内存 | 依赖上游 `DecodeOptions`，不能随意换成后处理 |
| `ImageGuard` 头部预检 | 挡图片炸弹（声明 40000×40000 的小 PNG 实测 413） | 限额写死在 `ImageLimits`，调整需同步测试 |
| 生产化配置**默认全关** | 不破坏本地开发与既有回归 | 上公网必须显式开鉴权与限流 |
| 指标为进程内计数、限流按 IP 固定窗口 | 不引入 Prometheus 客户端包，避免破坏 AOT 与零依赖主张 | 多实例部署时指标/配额不共享，需要外部方案 |
| 手写 JSON（设置、sidecar、日志） | AOT 下反射序列化会触发 `IL2026` / `IL3050` | 加字段需同步手写序列化与解析 |
| 预设数据化、四处共用 | 一次定义，桌面 / CLI / API / 测试台一致 | 新预设要在 `BatchPresets` 加并补测试 |
| 保留技术名、只改对外标识 | 避免打断 CI 路径与签名链 | 仓库里两套名字并存，见 3.2 |
| `.gitattributes` 统一换行 / 二进制标记 | Win/Linux 双矩阵 CI 不出现整文件 diff | 新增二进制扩展名记得补 `binary` 规则 |

## 9. 风险与债务

### 9.1 上游边界

- AVIF / JPEG XL **只能识别不能解码**；HEIF/HEIC **只解码**，不支持编码、alpha 与序列。
- HEVC 专利不在 MIT 授权内，商用前需法务评估。
- .NET 10 是硬门槛；`Stream` 整读进内存，单数组 2 GB 上限；上游 2.0 有破坏性变更（门面类名、像素格式枚举、WebP 默认有损）。
- 上游库年轻、单人维护 —— 靠锁版本 + 抽象层缓解，不自行修上游。

### 9.2 本项目取舍

- 处理层单线程标量、无 SIMD / 并行；JBIG2 / JPEG 2000 真实样本链路未跑（下载失败，**未伪造结果**）。
- 字体水印 / 矢量绘图 / 透视变换未做；若确需 TrueType 字形，应另加**真正可选**的 Skia 适配项目，不影响现有链路。
- 自动更新（X-6）未做，依赖分发渠道决策。
- 指标重启清零；无多实例共享、无持久化存储、无账号体系。

### 9.3 安全

- 私钥 `SimdCodecsDev.pfx` 与 GitHub PAT 均在本地且被忽略；**任何一次 `git add -f` 都可能造成泄露**，提交前用 `git check-ignore -v` 与 `git grep --cached` 复核。
- `ImageGuard` 是业务层限额，生产部署仍需在反向代理层限制请求体与并发。
- 测试台默认 `AllowAnyOrigin` CORS，公网部署需收紧或加鉴权。

## 10. 排障速查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `MSB4018` / `MSB3027`，DLL 被占用 | 5080 的 `dotnet` host 锁住 Core / Processing 输出 | 编译前停掉 `SimdCodecs.Api.exe` / 相关 dotnet 进程，编译完再启动 |
| AOT 发布找不到 `advapi32.lib` | Windows SDK 装在非标准盘 | 注入 `LIB` / `WindowsSdkDir` / `WindowsSDKVersion`；CI 用 `ilammy/msvc-dev-cmd@v1` |
| Linux GUI 冒烟起不来 | runner 缺 X11 / Skia 运行库 | 已在工作流补 `libx11-6` 等 9 个包并用 `xvfb-run -a` |
| 静态测试台 404 | 从解决方案根目录启动时内容根不对 | `WebApplicationOptions` 固定 `ContentRootPath = AppContext.BaseDirectory`、`WebRootPath = "wwwroot"`；csproj 把 `wwwroot/**` 复制到输出 |
| `--ApiRuntime__Auth__Enabled` 不生效 | 命令行配置用 `:` 分层 | 用 `--ApiRuntime:Auth:Enabled=true`，或依赖 `NormalizeRuntimeArg` 自动把 `__` 转成 `:` |
| `fatal: unable to write credential store` | 凭据助手回写被沙箱拒 | push 已成功，`git ls-remote` 复核，勿重推 |
| `makeappx unpack /d /tmp/...` 看不到目录 | Windows 工具不认 Git Bash 的 `/tmp` | 用 Python `zipfile` 直接读 MSIX 内清单 |
| 打出来的不是合法 zip / 中文名乱码 | GNU tar 不产 zip；编码问题 | 用 Windows `System32/tar.exe` 或 `Compress-Archive`，包内说明文件用英文名 |
| 便携 zip 里混进测试输出 | 在发布目录跑过 `--selftest` | 打包前删 `selftest-output/` 并核对条目数（基线 247 项） |
| Avalonia 主题报错 | 11.x 无 `FluentTheme.Mode`；`CornerRadius` Setter 需对象 | 用 `RequestedThemeVariant = ThemeVariant.Dark`；Setter 传 `new CornerRadius(6)` |
| `.gitignore` 规则不生效 | pattern 后跟了行尾注释 | 注释必须独立成行，改完用 `git check-ignore -v` 实测 |
| API Key 的 curl 验证被安全策略拦截 | 命令行带密钥被拦 | 改用 xUnit fixture（同参数自宿主）+ 5090 实例结构化日志作证据 |
| GitHub REST API 403 | 匿名/未带凭据 | 用 Actions 页面或匿名 jobs 接口 |
