# 04 工作日志

按轮次记录实跑结果、踩过的坑与设计决策。只记有跨会话价值的内容；临时路径、一次性搜索结果不记。

## 2026-11-11 第一轮：调研与可行性原型

**调研结论**：`Sdcb.SimdCodecs` 2.0 是 .NET 10 纯 C# 图片编解码 SDK（MIT、零原生依赖、AOT/WASM 友好），起因是 ImageSharp 3.2+ 引入 license key。它只做编解码，不做 resize/绘图/滤镜。

**原型**：Avalonia 11.3.23 + SimdCodecs 2.0.0，纯 C# 构建 UI（无 XAML）。`CodecService` 负责 文件字节↔Bgra32，`MainWindow` 负责 `WriteableBitmap(Bgra8888, Unpremul)` 显示。

**验证**：编译 0 警告 0 错误；`--selftest` 15/15 PASS；`--smoke` 3/3 PASS。

**踩坑**：
- `ImageCodecs.RegisteredCount` 在 XML 文档里存在但不公开，改用 `IsDecodable(ImageFormat.Heif)` 判断注册。
- `TryReadMetadata` 的 out 是可空引用类型，需 `?? ImageMetadata.Empty`。
- PNG 量化对平滑渐变会变大（914 B → 20981 B），对照片类才有效（186448 B → 60524 B，省 67.5%）。断言要按图类型分开写。

## 2026-11-11 第二轮：本地图片工作台

**新增**：`BatchService`（并行/可取消/错误隔离/输出名避让/多帧拆帧）、`BatchCli`（`--batch`）、`ImageItem`（队列 + 异步缩略图）、`BitmapFactory`。`CodecService` 扩展 `Inspect` / `Load(region)` / `Load(frameIndex)` / `LoadThumbnail` / `ExportTarget`。`MainWindow` 重构为三栏：队列（拖放/多选）、预览（框选裁剪 + 帧播放）、信息 + 批量面板。

**验证**：`--selftest` 30/30、`--smoke` 6/6、`--batch` 5 文件 + 逐帧 = 7 输出；28 MB 框架依赖单文件 exe 复跑自检/批量退出码 0。

**踩坑**：
- `DecodeOptions.Region` 是 `PixelRect?`，坐标在「缩放之后、EXIF 转正之前映射」的显示图像里，不是原图像素；连续框选要累加到基准区域。
- 无窗口测试不能用 `GetAwaiter().GetResult()` 阻塞：`ReloadAsync` 续体会 Post 回 UI 线程造成死锁。改为循环泵送 `Dispatcher.UIThread.RunJobs()` + 20 秒超时。
- NativeAOT 首次尝试失败：编译到 link 阶段缺 `advapi32.lib`，且沙箱阻止 `reg.exe` 查询注册表。已把反射 `Binding` 改为手写 `PropertyChanged` 同步，消除 IL2026 裁剪警告。

**API 要点**：`ImageFrame.CopyPixels(...)`；`IImageEncoderSession.AddFrame(w,h,PixelFormat,duration:...)` + `WriteRows(rows, rowCount)` + `Commit()` 可生成多帧 GIF。

## 2026-11-11 第三轮：拆共享类库 + Web API + 测试台

**工程**：`SimdCodecsWorkbench.slnx`（.NET 10 的 .slnx 格式）收口三项目。`SimdCodecs.Core` 只依赖 SimdCodecs；Viewer 用 `GlobalUsings.cs` 的 `global using SimdCodecs.Core;` 保持源码零改动。

### 踩坑与修正

- **跳过被当成失败**：`BatchCli.Run` 用 `results.Any(r => !r.Ok)` 判退出码，预设过滤出的 `Skipped` 项让整批返回 1；进度里也显示 `FAIL`。改为 `!r.Ok && !r.Skipped`，进度显示 `SKIP`；桌面队列同步改为「[跳过]」且不算错误。
- **AOT 反射警告回归**：裸像素 sidecar 用 `JsonSerializer.Serialize(匿名对象)` 触发 IL2026 / IL3050。改成 `StringBuilder` + `JsonEncodedText.Encode` 手写 JSON，重新 AOT 发布后警告计数 0。
- **自检断言写错**：反色后 128 应为 127，我却断言 `< 10`；亮度 +50 直接打满 255 不利于验证，改为 +20（理论 179）。修正后 54/54。
- **Otsu 在纯黑白图上阈值取 0**：类间方差在多个 t 处并列最大，算法取第一个。断言只检文本行数与墨迹占比，不硬编码阈值。
- **发布仍需先停进程**：本轮先停 `SimdCodecs.Api`(2460) 与 `SimdCodecsViewer`(8912) 再发布，完成后重启为 5556 / 9164。
- MSBuild 尝试调 `reg.exe` 仍被沙箱黑名单拦截，不影响链接与产物。

### 踩坑与修正

- **文件锁**：5080 服务进程锁住 `SimdCodecs.Core.dll` 导致 MSB3027；编译前先停服务，编译完再重启。
- **`BatchPresets.All` 是 `IReadOnlyList`**：`.Length` 不存在，改 `.Count`。

- **Git Bash tar 不产 zip**：GNU tar 的 `-a` 只切换压缩层不换容器；改用 Windows 自带 bsdtar（`/c/Windows/System32/tar.exe`）。

## 第十七轮（2026-11-12）：修复远端 CI AOT job 误判（pwsh × GUI 子系统 exe）

远端 run #2（`89f3c53`）双矩阵回归全绿，但 **NativeAOT job 在「组合自检」步骤 2 秒失败**。发布本身成功，排除编译与模型裁剪问题。

### 根因（本机复现实证）

Viewer 是 `OutputType WinExe`（GUI 子系统），**pwsh 捕获 GUI 子系统 exe 的 stdout 与退出码不可靠**：

| 调用方式 | 输出 | 退出码 |
| --- | --- | --- |
| Git Bash 重定向到文件 | 85 行完整报告 | 0（正确） |
| pwsh 捕获赋值 + 重定向合并 | **0 行** | **空/null**（CI 上 `code -ne 0` 判真 → throw "exit code "） |
| pwsh 直接运行（run #1 的 batch 步骤） | 不捕获 | 步骤级退出码正常 |

## 第二十一轮（2026-11-12）：深色模式标题栏修复

用户报障：暗色模式下窗口内容是深色，但 Windows 系统标题栏仍是白色（截图为证）。根因与修复如下。

### 根因

窗口内容由 Avalonia 绘制（跟随 `RequestedThemeVariant=Dark`），但标题栏由 Windows DWM 绘制，**不会自动跟随应用主题**——需要显式调用 `DwmSetWindowAttribute(DWMWA_USE_IMMERSIVE_DARK_MODE)`。另外 Avalonia Win32 的 `WindowImpl.SetFrameThemeVariant` 只认**系统**颜色主题（不看应用 ThemeVariant），Win11（build ≥ 22000）上会在显示流程中把该属性重设回系统值。

### 修复（`SimdCodecsViewer/DarkTitleBar.cs`，MainWindow 构造挂 `DarkTitleBar.Attach`）

1. `DWMWA_USE_IMMERSIVE_DARK_MODE(20)` 设 1，旧 Win10 build 回退 19；非 Windows 为 no-op；失败静默（不影响功能）。
2. Win11 增强：`DWMWA_CAPTION_COLOR(35)` 设为 UI 底色 `#141518`、`DWMWA_TEXT_COLOR(36)` 设为主文字色 `#E8EAED`，标题栏与内容完全融合；Win10 不认识这两个属性，忽略即可。
3. 时序加固：`Opened` → 立即 Apply + `Dispatcher.Post`（Background）+ 150 ms 后再 Apply，覆盖 Avalonia 平台层的重设；订阅 `PlatformSettings.ColorValuesChanged`，运行期用户切换系统深浅色后再覆盖回来。
4. NativeAOT 友好：显式 `DllImport`，无反射。

### 验证

- 实机读回：启动 GUI，按 **PID 过滤**枚举主窗口 → `DwmGetWindowAttribute(20)` 读回 **1**（PASS）。本机 Win10 22H2（19045）不支持 35/36（返回 `E_INVALIDARG`，属预期），标题栏走标准暗色。
- **调试教训**：最初三轮「失败」是**实验污染**——用户正开着旧实例（PID 23544），`FindWindowW` 按标题抓到的是它（跑修复前代码），读回 0；加诊断代码后对比发现内外 HWND 属于不同进程，改按 PID 过滤枚举后才测到正确窗口。
- 回归：Release 0 警告；selftest 64/64、apitest 46/46、xUnit 97/97；smoke 修复后全绿。
- smoke 顺手加固：标题断言从「工作台」（中文）改为语言无关的 `Contains("CodecLoom")`——本机 settings.json 残留 `Language=en` 曾让 smoke 误报失败，验证不应依赖用户本机设置。

### 备注

- 本机 NativeAOT 复验未能进行：**本机 Windows SDK 的 `Lib\10.0.26100.0` 目录为空（`advapi32.lib` 等_um_ 库物理缺失，SDK 安装不完整）**，链接阶段 LNK1181——注入 `WindowsSdkDir` / `LIB` / `INCLUDE` 也无效（文件不存在）。改动本身是标准 `DllImport`（无反射），AOT 兼容风险极低；以 CI aot job（完整 SDK + selftest 64 项 / PASS ≥ 60 / 体积 ≥ 35 MB 断言）为权威验证。**新债务登记：本机若需 NativeAOT 开发，需先补装 SDK 的「Windows SDK for Desktop C++ x64 Apps」组件。**
- Win10 上标题栏为系统标准暗色（非同色融合）；Win11 上与 UI 底色一致。安装包分发的产物同样生效。
