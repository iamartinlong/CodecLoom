# 01 规划方案

## 1. 背景与调研结论

调研来源：微信公众号「.NET骚操作」2026-11-11《SimdCodecs 2.0：一套 API 解所有图片》，以及 GitHub 仓库、v2.0.0 发布说明、项目主页、已知缺口文档、NuGet 页面。

结论：`Sdcb.SimdCodecs` 2.0 不是终端产品，而是 **.NET 10 的纯 C# 图片编解码 SDK**。它把 12+ 种图片格式收敛到 `ImageCodecs` 一套门面 API，MIT 许可、零原生 DLL、可跑 NativeAOT 与浏览器 WASM，性能对标 libjpeg-turbo / libpng / libheif。作者的直接动因是 ImageSharp 3.2+ 引入 license key。

它明确定位为「图片 I/O 基础设施」：**只做编解码，不提供 resize、绘图、滤镜、色调映射**。这意味着它适合用来造产品，本身不是产品；图像处理能力必须由上层补齐。

## 2. 项目目标与非目标

**目标**

1. 验证「SimdCodecs + Avalonia」能否组成可用的本地图片客户端，重点覆盖 Avalonia 自带解码器打不开的格式（HEIC / TIFF / JPEG 2000 / JBIG2 / QOI / Netpbm）。
2. 把核心编解码能力做成**零 UI 依赖的共享类库**，使桌面、命令行、Web API 三种入口复用同一份实现。
3. 形成一条可演示、可验证、可发布的端到端链路：解码 → 显示/预检 → 转换 → 批量 → HTTP 服务。
4. 把上游能力边界与安全风险显式登记，避免把「已注册」误当成「已验证」。

**非目标**

- 不做完整图片编辑器：**字体水印 / 矢量绘图 / 透视变换 / 图层**不做；基础滤镜与任意尺寸缩放由本项目的纯托管处理层 `SimdCodecs.Processing` 提供（S5 后已从非目标转成能力）。
- 不替代 ImageSharp，也不解决其授权问题之外的生态问题。
- 不实现 AVIF / JPEG XL 解码、HEIF 编码（上游 2.0 不支持）。
- 本阶段不做公网部署、多租户、账号体系。

## 3. 产品形态

| 入口 | 形态 | 主要价值 |
| --- | --- | --- |
| `SimdCodecsViewer` | Avalonia 桌面工作台 + CLI | 本地优先、图不上传；一键预设批量、多帧/多页浏览、框选裁剪、图像处理与裸像素导出 |
| `SimdCodecs.Api` | ASP.NET Core 图片处理服务 | 上传前置校验、格式协商、缩略图、批量/拆页 zip、处理与 CV 像素端点，可被任何前端调用 |
| `wwwroot/index.html` | 无依赖 Web 测试台 | 让 API 可直接点用，兼作能力清单、预设选择与 curl 文档 |
| `SimdCodecs.Processing` | 可选纯托管处理层 | 任意尺寸缩放、滤镜、几何水印、Gray8/BGR 布局，零原生 DLL、AOT 安全 |

## 4. 架构

```
  Avalonia 窗口 ─┐
  CLI --batch   ─┼──┬─ SimdCodecs.Core（零 UI / 零 Web / 零原生依赖）
  ASP.NET Core ──┘  │    CodecService · ICodecService · BatchService
                    │    BatchPresets · ImageGuard · _manifest.csv
                    │              │
                    │              └─ Sdcb.SimdCodecs 2.0.0 + .Heif 2.0.0
                    │
                    └─ SimdCodecs.Processing（可选，只依赖 BCL）
                         ImageOps · ImageProcessor · CvInput · PixelLayout
```

分层原则：

- **Core**：只依赖 `Sdcb.SimdCodecs`，不引用 Avalonia / ASP.NET Core / Processing。提供文件路径版与内存字节版两套入口。
- **处理层**：与 Core 平级的可选项目，输入输出都是裸 `byte[]`，因此 Core 不因它沾上任何原生依赖；桌面 / API 按需引用。
- **桌面层**：`Bgra32 → WriteableBitmap(Bgra8888, Unpremul)`，负责控件、拖放、帧播放、裁剪交互与处理参数。
- **服务层**：全程内存态，`ImageGuard` 在解码前只读文件头校验；响应体直接写编码后字节 / zip / 裸像素，不落临时盘。
- **接口层**：`ICodecService` 隔离上游实现，便于锁版本与回退到 Magick.NET / ImageSharp。

## 5. 技术选型与理由

| 选择 | 理由 |
| --- | --- |
| .NET 10 / `net10.0` | SimdCodecs 2.0 的硬性要求；也是 AOT / WASM 能力的前提 |
| Avalonia 11.3.23 | 跨平台、自带 Skia 渲染层，可补 SimdCodecs 缺失的绘制能力 |
| 纯 C# 构建 UI（无 XAML） | 避免 XAML 反射在 AOT 裁剪下的绑定问题，减少 IL2026 警告 |
| `PixelFormat.Bgra32` 统一像素 | Avalonia `WriteableBitmap` 的 `Bgra8888` 逐行直拷，不假设 `Stride == RowBytes` |
| HEIF 独立 opt-in 包 + 显式 `Register` | 门面包刻意不引用它；HEVC 专利不包含在 MIT 授权内 |
| 手动 multipart `ReadFormAsync` | 便于统一大小上限、格式白名单与 ProblemDetails 错误响应 |
| `WebApplicationOptions` 指定 ContentRoot | 避免从解决方案根目录启动时静态页 404（详见工作日志） |
| 处理层用纯 BCL 而非 SkiaSharp | 保住「零原生 DLL + NativeAOT」主线；缩放/色调/几何水印都是数组运算。代价是不渲染文字字形，详见 `03-待办清单.md` |
| `BatchPreset` 把业务动作数据化 | 一次定义，桌面 / CLI / API / 测试台四处共用；服务端从 `/api/presets` 动态生成 UI |
| 手写 JSON 而非反射序列化 | sidecar 字段固定，`JsonSerializer.Serialize(匿名对象)` 会触发 IL2026 / IL3050 |

## 6. 关键设计决策

1. **解码期能力优先**：`DecodeOptions.ScaleDenominator` / `Region` / `ApplyOrientation` 都在解码阶段完成，不先解全图再缩放或裁剪。
2. **头部预检挡图片炸弹**：`ImageGuard` 限制单文件 32 MB、80 MP、帧数与格式白名单；实测 CRC 正确但声明 40000×40000 的 PNG 在 Core 与 HTTP 两层均返回 413。
3. **批量错误隔离**：单文件失败不影响整批，zip 内附 `_report.txt` 逐项报告；取消令牌不留半截文件。
4. **元数据透传**：保存时把原图 EXIF / XMP / ICC 交给编码器。
5. **抽象层兜底**：上游库发布仅两天、单人维护，必须保留替换实现的口子。
6. **预设即产品**：把「源格式过滤 + 目标 + 质量 + 拆页 + 页码」打包成一个 ID，用户不必理解格式枚举；跳过与失败分开统计，避免预设误报失败。
7. **CV 输入要能被真实算法消费**：`/api/pixels` 返回连续字节并附带 Otsu 阈值与行投影结果，用真实下游算子而不是桩调用验证布局正确。

## 7. 能力边界与风险登记

| 项 | 类型 | 影响 / 处置 |
| --- | --- | --- |
| AVIF / JPEG XL 只能识别不能解码 | 上游 | 明确拒绝并给出可读错误，等上游 |
| HEIF 不支持编码 / alpha / 序列 | 上游 | 只做输入侧 |
| HEVC 专利 | 法务 | MIT 不授予专利许可，商用需单独评估 |
| `Stream` 仍整读内存、单数组 2 GB 上限 | 上游架构 | 大图需压测确认边界 |
| 只支持 .NET 10 | 上游 | 老项目无法引入 |
| 库 2.0 发布两天、Star 约 120、单人维护 | 供应链 | 锁版本 2.0.0 + `ICodecService` 抽象 |
| 2.0 有破坏性变更（门面类名、像素格式枚举、WebP 默认有损） | 版本 | 锁版本，升级需回归 |
| NativeAOT 依赖本机 MSVC 链接工具链 | 环境 | 见实施计划 S4 与工作日志 |
| 字体水印 / 矢量绘图 / 透视变换未做 | 能力 | 纯托管处理层已覆盖缩放、色调、灰度、几何水印；需要 TrueType 字形时可另加可选 Skia 适配项目 |
| 处理层为单线程标量实现 | 性能 | 未做 SIMD / 并行；大图需压测，必要时可换 AVX2 或接上游 SIMD 能力 |
| 几何水印不渲染文字 | 产品体验 | 文本经 FNV-1a 决定斜纹相位，图案随文本变化但不可读；属明确取舍 |

## 8. 验收口径

每一轮推进都按同一口径验收，不接受「编译过即完成」：

1. `dotnet build SimdCodecsWorkbench.slnx -c Release` **0 警告 0 错误**。
2. 桌面 `--selftest`、`--smoke`，API `--apitest` 全部 PASS，且新增能力必须有对应断言。
3. 发布产物（桌面单文件 exe、API publish 目录）复跑自检/集成测试退出码为 0。
4. 结果写回 `03-待办清单.md` 与 `04-工作日志.md`；无法验证的项标注「阻塞」并写清前置条件，不以推测代替实测。
